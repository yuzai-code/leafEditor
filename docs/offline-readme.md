# 笔记编辑器离线功能

本文档介绍了笔记编辑器的离线存储功能实现和使用方法。

## 功能概述

笔记编辑器的离线功能基于 SQLite WASM 实现，使用 IndexedDB 持久化数据。主要功能包括：

1. **离线笔记管理**：在没有网络连接的情况下创建、编辑、删除笔记
2. **离线分类管理**：管理笔记分类
3. **离线标签管理**：为笔记添加标签
4. **本地数据持久化**：将数据保存到浏览器的 IndexedDB 中

## 技术栈

- **SQLite WASM**：通过 sql.js 在浏览器中运行 SQLite 数据库
- **IndexedDB**：用于持久化 SQLite 数据库文件
- **Vue 3**：前端框架
- **Pinia**：状态管理
- **TypeScript**：类型安全的 JavaScript 超集

## 使用方法

### 基本操作

笔记应用会在启动时自动初始化离线数据库，所有操作都会自动保存到本地数据库中。

#### 创建笔记

1. 点击"新建笔记"按钮
2. 输入笔记标题、内容和其他信息
3. 选择分类和标签
4. 点击"保存"按钮

#### 编辑笔记

1. 从笔记列表中选择要编辑的笔记
2. 修改笔记内容
3. 点击"保存"按钮

#### 删除笔记

1. 从笔记列表中选择要删除的笔记
2. 点击"删除"按钮
3. 确认删除操作

### 数据管理

#### 导出数据

目前的实现中，数据仅保存在浏览器的 IndexedDB 中，尚未实现数据导出功能。

#### 清除数据

要清除本地数据，可以清除浏览器的 IndexedDB 存储：

1. 打开开发者工具（F12）
2. 切换到"应用程序"或"存储"标签页
3. 找到"IndexedDB"部分
4. 删除"NotesDatabase"数据库

## 实现细节

### 架构设计

离线功能采用数据提供者模式实现，主要组件包括：

- **SqliteClient**：SQLite 数据库客户端，负责数据库的初始化和底层操作
- **DataProvider**：数据提供者接口，定义了笔记、分类和标签的操作方法
- **OfflineDataProvider**：基于 SQLite 实现的离线数据提供者
- **DataProviderFactory**：数据提供者工厂，根据网络状态选择数据提供者
- **API 适配器**：将现有的 API 调用适配到数据提供者上

### 数据模型

数据库包含以下表：

- **notes**：存储笔记数据
- **categories**：存储分类数据
- **tags**：存储标签数据
- **note_tags**：存储笔记和标签的关联关系

### 离线优先策略

应用采用"离线优先"策略，所有操作首先在本地完成，然后在网络连接可用时同步到服务器。

## 常见问题

### 数据丢失

问题：关闭浏览器后数据丢失

解决方案：确保浏览器没有设置为"隐私浏览"模式，并且没有禁用 IndexedDB。

### 性能问题

问题：大量数据时操作变慢

解决方案：目前的实现针对中小规模的笔记量进行了优化，如果遇到性能问题，可以考虑分页加载和优化查询。
